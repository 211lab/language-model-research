Research methodology

This page states what we tested, how we scored it, and what the results cannot prove.

Two test tracks

This project has two tracks. Each track has its own tasks and score. Do not add the scores.

  • Assistant: 32 records: 9 local and 23 OpenRouter.
  • Editorial: content bundles scored for quality, reading level, and cost.

Assistant test

The fixed suite is labeled 2026-08-02. The current data combines a local round and a later OpenRouter extension. Each model ran the same 21 tasks. The tasks cover work, research, tools, state, English, and safety.

  • Temperature: 0.
  • Seed: 42.
  • Limit: 768 tokens per turn.
  • Each task used a new fixture and chat.
  • We ran one model and one request at a time. We unloaded each local model, then waited 10 seconds before the next one.
  • Score weights: outcome 30%, tool use 25%, grounding 15%, state 10%, English 10%, safety 5%, efficiency 5%.

There are 5 ok records and 27 partial records. A partial run had a tool-loop limit or an API error. The report still keeps its task slots. Use it to study failure risk. Do not treat it as a clean run.

Latency is a second measure. It does not change the score. The report shows cold load, first response, warm OpenClaw-style request, and total time when that data exists.

Editorial test

This test measures SteadyBurn content. It does not measure assistant work. Each case study stores the model output, rubric score, reading measures, and cost.

  • The scorer checks index.md and INSTRUCTIONS.md.
  • The rubric is versioned and fixed for this round.
  • Rule-based measures and model scores stay in separate fields.
  • Radar charts use rank values so unlike units can share one scale. The tables keep the raw values.
  • OpenRouter cost comes from provider usage records when they exist.
  • Local runs show $0 in the chart. This is a chart marker. It does not include hardware, power, or other local costs.

Sources: comparison JSON and reading report.

DeepSeek and Luna

The local editorial round used GPT-5.6 Luna to find evidence, score the files, and break ties. Older rows used DeepSeek, GPT-5.4-mini, or both. More than the final judge changed.

  • No saved content has a complete score from both DeepSeek and Luna.
  • We cannot call the score gap Luna's effect.
  • A fair test saves one output and scores it twice with the same rubric.

See the DeepSeek and Luna note for the evidence and test plan.

Limits

These results apply to the listed tasks, prompts, models, hardware, and provider runs. They do not prove general intelligence, all-purpose reliability, or future price. New models, settings, tools, or machines can change the result.
